# Infrastructure

Petfinder's AWS infrastructure: TypeScript with [cdktn](https://cdktn.io) (CDK Terrain) and `@cdktn/provider-aws`, deployed with [OpenTofu](https://opentofu.org). It's a standalone npm package outside the Nx workspace, so run every command from this folder.

> **Configuration** defines what is provisioned. **Stacks** compose modules. **Modules** implement resources. **`BaseStack`** sets the shared conventions. **`main.ts`** orchestrates.

## Quick start

```bash
brew install opentofu              # needed for diff, deploy and destroy, not for synth
cd infrastructure && npm install
npm test                           # config defaults, overrides and validation
npm run synth:dev                  # generate Terraform JSON into cdktn.out/
npm run diff:dev                   # what would change in AWS
```

## Layout

```
infrastructure/
├── variables.ts             # all config: types, defaults, per-env overrides, validation
├── main.ts                  # creates one stack per env (or just INFRA_ENV) and synthesizes
├── stacks/
│   ├── base-stack.ts        # abstract BaseStack: config, provider, account guard, state, tags, naming
│   ├── application-stack.ts # networking + load balancer + rds + ECS services
│   ├── registry-stack.ts    # shared ECR repositories for the app images
│   ├── state-backend.ts     # S3 (or floci) state backend for every deployable stack
│   └── provider.ts          # AWS provider with standard tags (shared with bootstrap)
├── modules/
│   ├── networking/          # VPC, subnets, routing, alb/app/ui/db security groups
│   ├── rds/                 # RDS Postgres, password kept in Secrets Manager by RDS
│   ├── ecr/                 # ECR repository: immutable tags, scan on push, image expiry
│   ├── load-balancer/       # ALB, api/ui target groups, HTTP listener with /api routing
│   ├── ecs/                 # ECS cluster and a Fargate service construct (roles, logs, task, service)
│   └── s3/                  # private bucket: SSE, public access block, TLS-only
├── bootstrap/               # S3 state bucket, deployed on its own first
├── local/                   # floci + Postgres for local work (see local/README.md)
├── tests/variables.test.ts  # config tests
├── scripts/require-tofu.sh  # preflight for diff/deploy/destroy
├── scripts/push-images.sh   # build the api and ui images and push them to ECR
└── cdktf.json  package.json  tsconfig.json
```

## Conventions

### Architecture

| Layer | Does | Never |
| --- | --- | --- |
| `variables.ts` | Holds every non-sensitive setting for `dev`, `uat`, `staging` and `prod`, and validates it | Holds secrets or account IDs (those come from `.env`) |
| `BaseStack` | Provider, account guard, remote state, tags and naming for every stack | Creates application resources |
| Stacks | Extend `BaseStack`, compose modules, pass values between them, decide what's provisioned from flags, expose outputs | Contain resource details that belong in a module |
| Modules | Build one capability from typed props, apply secure defaults, expose only the IDs others need | Import `variables.ts`, check the env name, hardcode an account, or set up a backend |
| `main.ts` | Picks the envs, creates the stacks, calls `app.synth()` | Builds resources or holds config |

- **One implementation for every env.** There's one `ApplicationStack` class, created once per environment, never a class per env.
- **Flags, not env checks.** Optional infra is switched with config such as `if (config.rdsProxy.enabled)`, never `if (environment === 'prod')`.
- **Provisioning flags are separate from operational flags.** `enabled` creates the resource. Something like `scheduleEnabled` only changes how it behaves. Turning off a provisioning flag **destroys** resources, so read the diff.
- **YAGNI.** Add a module, stack or config section only when a ticket needs it. No empty placeholders.
- **Across stacks, use outputs.** Values move between stacks only through explicit outputs, never by relying on deploy order.

### Configuration

- **Explicit composition.** Each env spreads `defaults`, and each nested section spreads its own defaults, because object spreads are shallow:

  ```ts
  prod: {
    ...defaults,
    target: awsProfile('prod'),
    networking: { ...defaults.networking, cidr: '10.40.0.0/16' },
    rds: { ...defaults.rds, instanceClass: 'db.t4g.small', backupRetentionDays: 7, deletionProtection: true }
  }
  ```

- **Fail early, never fix silently.** `validateConfig` runs in every stack before anything is built, and `validateEnvironments` checks rules across envs, such as non-overlapping CIDRs. A bad config stops synth with every problem listed.
- **Secrets stay out.** `INFRA_AWS_ACCOUNT_ID` (required) and `INFRA_STATE_BUCKET` (optional) come from the repo's root `.env`. Database passwords are generated by AWS and kept in Secrets Manager. Nothing sensitive goes in code, config or outputs.

| Env | CIDR | DB | Backups | Deletion protection |
| --- | --- | --- | --- | --- |
| `dev` | 10.10.0.0/16 | `db.t4g.micro` | 1 day | off |
| `uat` | 10.20.0.0/16 | `db.t4g.micro` | 1 day | off |
| `staging` | 10.30.0.0/16 | `db.t4g.small` | 7 days | off |
| `prod` | 10.40.0.0/16 | `db.t4g.small` | 7 days | on (database with a final snapshot, and the load balancer) |

### Naming and tags

- **Stack IDs:** `<env>-<component>`, for example `dev-application`. Account-wide stacks have no env: `bootstrap` and `registry`.
- **Resource names:** `petfinder-<env>-<resource>`, for example `petfinder-dev-db` or `petfinder-prod-app`. Use `this.resourceName('<resource>')` in a stack.
- **Construct IDs are part of the Terraform address.** Renaming one or moving it to another parent replaces the resource. Keep them stable, and check the diff for replacements.
- **Tags on every resource**, set by the provider's `default_tags`:

  | Tag | Value |
  | --- | --- |
  | `Project` | `petfinder` |
  | `Environment` | `dev`, `uat`, `staging`, `prod` or `local` |
  | `Component` | the stack's component, for example `application` |
  | `ManagedBy` | `cdktn` |
  | `Owner` | `platform` |

### State and accounts

- **Remote state:** S3 bucket `petfinder-tfstate-<account id>`, one key per stack: `<env>/<component>/terraform.tfstate`, or `shared/registry/terraform.tfstate` for the registry. It uses `encrypt` and `use_lockfile` (OpenTofu's native S3 locking).
- **State bucket:** versioned, encrypted, blocks public access, denies non-TLS requests and has `prevent_destroy`. It's created by `bootstrap/`, whose own state is the git-ignored file `bootstrap/.state/terraform.tfstate`. Back that file up.
- **Account guard:** each env uses the AWS profile `petfinder-<env>`, and `allowed_account_ids` refuses any account other than `INFRA_AWS_ACCOUNT_ID`.
- **State is sensitive.** Never commit it. `.gitignore` covers `*.tfstate`, `.state/` and `cdktn.out/`.

### Security defaults

- Databases are in private subnets, aren't publicly accessible, and are encrypted at rest.
- The VPC's default security group has no rules. Every rule is explicit and as narrow as possible:
  - The ALB takes `80` from the internet and can only reach the api and ui ports.
  - The api (`app`) and `ui` groups accept traffic only from the ALB.
  - The database accepts its port only from `app`.
- Buckets are private, encrypted and TLS-only.
- Prod must have database and load balancer deletion protection and at least 7 days of backups. Validation enforces all three.

### Code style

- Comments only for non-obvious logic: the *why*, not the *what*.
- No numbered filenames.
- Pin compatible versions: cdktn `~0.25`, `@cdktn/provider-aws` `~26.0`, AWS provider `~> 6.0`, OpenTofu `>= 1.13`.

## Adding a capability

Example: RDS Proxy.

1. **Config:** in `variables.ts`, add `rdsProxy: { enabled: boolean, ... }` to `EnvironmentConfig`, set a default in `defaults`, and override it in the envs that need it. Add validation for any invalid combinations.
2. **Test:** cover the new defaults and validation in `tests/variables.test.ts`.
3. **Module:** create `modules/rds-proxy/index.ts`, which takes typed props (for example the database ARN, subnets and security groups) and exposes `endpoint`.
4. **Stack:** compose it in the stack:

   ```ts
   const proxy = rdsProxy.enabled ? new RdsProxyModule(this, 'rds-proxy', { ... }) : undefined;
   ```

5. **Verify:** run `npm test`, `npm run synth:<env>` with the flag on and off, and `npm run diff:<env>`.

Replace `dev` with `uat`, `staging`, `prod` or `local`.

| Task | Command |
| --- | --- |
| Config tests | `npm test` |
| Type-check | `npm run typecheck` |
| Synthesize one env, or all | `npm run synth:dev`, or `npm run synth` |
| Plan | `npm run diff:dev` |
| Apply (asks for approval on AWS) | `npm run deploy:dev` |
| Tear down | `npm run destroy:dev` |
| Create the state bucket (once) | `npm run bootstrap` |
| Plan or apply the shared registry | `npm run diff:registry`, `npm run deploy:registry` |
| Build and push the app images | `npm run push:images` (tag defaults to the commit SHA) |

## First-time AWS setup

1. Set `INFRA_AWS_ACCOUNT_ID` in the repo's root `.env`. See `.env.example`.
2. Create the AWS profiles `petfinder-dev`, `petfinder-uat`, `petfinder-staging` and `petfinder-prod` (for example with `aws configure sso`), then log in: `aws sso login --profile petfinder-dev`.
3. `npm run bootstrap`: creates the state bucket with the `petfinder-dev` profile.
4. `npm run deploy:registry`: creates the ECR repositories, also with `petfinder-dev`.
5. `npm run push:images`: needs the AWS CLI (`brew install awscli`) and a clean git tree. It prints the tag it pushed.
6. `INFRA_IMAGE_TAG=<tag> npm run diff:dev`, then `INFRA_IMAGE_TAG=<tag> npm run deploy:dev`. Open the `app_url` output.

Every synth, diff and deploy of an application stack needs `INFRA_IMAGE_TAG`, because the task definitions pin that tag. Set it in the root `.env`, or prefix the command. Deploying a new tag rolls both services. If the new tasks fail their health checks, ECS rolls back.

## What's deployed

The `application` stack in each env contains:

- **Networking:** a VPC across 2 AZs, with a public and a private `/24` subnet in each. Only the public route table routes to the internet gateway. NAT is off (`networking.singleNatGateway`).
- **Security groups:**
  - `alb`: HTTP from the internet, egress only to `app` and `ui`.
  - `app` (api): ingress only from `alb`, and all egress.
  - `ui`: ingress only from `alb`, and HTTPS egress.
  - `db`: only the database port, from `app`.
- **Load balancer:** an internet-facing ALB on HTTP `:80`.
  - `/api` and `/api/*` go to the api target group (`services.api`: port 3000, health `/api`).
  - Everything else goes to the ui target group (`services.ui`: port 8080, health `/healthz`).
- **ECS:** cluster `petfinder-<env>` and two Fargate services, `petfinder-<env>-api` and `petfinder-<env>-ui`.
  - Tasks are ARM64 and run in the public subnets with a public IP (no NAT), behind the `app` and `ui` security groups.
  - Each service has its own log group `/ecs/<service>` (14 days, 90 in prod), an execution role, and an empty task role. Only the api's execution role can read the RDS secret.
  - The api gets `DB_HOST`, `DB_PORT` and `DB_NAME`, plus `DB_USERNAME` and `DB_PASSWORD` from the RDS secret. It also gets `DB_SSL=true` with the RDS CA bundle baked into the image, and `DB_RUN_MIGRATIONS` from `ecs.runMigrations`.
  - Sizes come from `services.<app>`: `cpu`, `memory` (a valid Fargate pair) and `desiredCount`. Each is 0.25 vCPU / 512 MiB with 1 task, or 2 tasks in prod.
  - Deployments use the circuit breaker with rollback.
- **Database:** RDS Postgres 17 on `gp3`, with the master password in Secrets Manager (`manage_master_user_password`).
- **Outputs:** `vpc_id`, `public_subnet_ids`, `private_subnet_ids`, `app_security_group_id`, `ui_security_group_id`, `alb_security_group_id`, `db_security_group_id`, `alb_dns_name`, `app_url`, `api_target_group_arn`, `ui_target_group_arn`, `ecs_cluster_name`, `api_service_name`, `ui_service_name`, `db_endpoint`, `db_port`, `db_name` and `db_secret_arn`.

The account-wide `registry` stack contains:

- **ECR repositories** `petfinder/api` and `petfinder/ui`, shared by every env. An image is built once and the same tag is promoted from dev to prod, so prod runs exactly what was tested. Tags are immutable, images are scanned on push and encrypted, untagged images expire after a day, and only the last `registry.keepImages` (30) are kept.
- **Images** are built for `linux/arm64`, because Fargate on Graviton is cheaper than x86 and builds natively on Apple silicon. `push-images.sh` refuses the tag `latest` and an uncommitted tree, so every tag names one commit.
- **Outputs:** `api_repository_url` and `ui_repository_url`.

## Verifying a change

Only the configuration has automated tests. Check resources with synth and diff:

1. `npm test`
2. `npm run synth:dev`, then read `cdktn.out/stacks/dev-application/cdk.tf.json`.
3. `npm run diff:dev`. It should show only the intended changes, and no unexpected replacements or destroys.

For local work against the floci emulator, see [local/README.md](local/README.md).
